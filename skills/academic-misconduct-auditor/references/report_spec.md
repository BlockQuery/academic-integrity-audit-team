# 报告结构规范

## 设计原则

委托方（举报人、单位纪检、期刊编辑）通常只看前三页。所以报告必须做到：**第一页给出结论与依据强度，后面才是逐条论证**。倒金字塔，不是侦探小说。

三个必须满足的形式要求：

1. **每个结论可回溯到章节编号**。摘要说"存在 3 处需说明的疑点"，正文对应 §3.1 / §3.4 / §3.7。
2. **每个数字带口径**。不写"发表论文 43 篇"，写"发表论文 43 篇（OpenAlex 收录 31 篇 + CNKI 补检 12 篇，去重后；检索日期 2026-11-12）"。
3. **每一维单独成节，用统一五段式**：结论等级 → 发现 → 证据 → 反向证据 → 说明建议。缺任一段视为不合格。

---

## 章节结构

### 封面与摘要（1 页）

| 项目 | 要求 |
|---|---|
| 报告标题 | `学术成果审计报告：<姓名>（<单位>）` |
| 审计对象 | 姓名、单位、职称、研究方向、ORCID/OpenAlex ID |
| 委托用途 | 自查 / 单位审查 / 举报准备 / 媒体调查 |
| 审计期间 | 数据截止日 |
| 审计范围 | 论文 N 篇，年份区间，数据源清单 |
| **综合结论** | 四档之一 + 一句话 |
| **疑点清单** | 最多 5 条，每条一行：编号 + 一句话 + 等级 |
| 声明 | 本报告基于公开数据，不构成学术不端认定 |

摘要中的疑点必须按严重度排序，且**必须包含至少一条"已排除"的说明**（例如"经核查，X 篇跨专业论文系数据库作者误并，已剔除，不构成疑点"）。这条是可信度的关键——只列罪证的报告一看就是有立场的。

### §1 审计方法与口径

必须写清：

- 数据源清单（含 API 与人工检索）
- 检索式（逐条列出，含命中数与纳入数）
- 身份确认方式（候选人列表、确认依据、用户确认时间）
- 去重规则（同一论文多库重复如何处理、中英文双版如何认定）
- **覆盖盲区**（照抄 `data_sources.md` 第六节的相关行）
- 判定标准来源（六维评分卡，标注版本）

这一节写得越细，报告越难被推翻。

### §3 六维审核

每维固定五段式。示例：

```
### 3.2 专业相关性（D2）—— 等级：B（存在需说明的疑点）

**发现**
18 篇论文中 6 篇的主题超出"示例学科颌面影像"这一主线，涉及肿瘤基因组学（2 篇）、
神经发育（1 篇）、深度学习算法（3 篇）。

**证据**
| 编号 | 年份 | 论文 | DOI | 本人位次 | 主题 |
|---|---|---|---|---|---|
| E1 | 2022 | Comprehensive Analysis of TPX2... | 10.xxxx | 中间（第 5/8） | 肿瘤基因组学 |
| ... |

【事实】上表 6 篇论文的主题标签均来自 OpenAlex primary_topic，已核对标题与摘要。
【推演】其中 3 篇深度学习论文与本人颅面影像工作构成技术主线（同一数据集、同一合作团队），
属正常交叉；另 3 篇（肿瘤基因组学 2 篇、神经发育 1 篇）与主线无关。
【推测】无关论文可能源于同名作者误并或一次性合作，需核对原文署名单位。

**反向证据**
- 6 篇中 5 篇本人为中间位次，符合"参与合作"而非"主导"的模式；
- 深度学习 3 篇的合作者为同一实验室，且该实验室在本人其他论文中担任通讯作者，
  构成稳定的跨学科合作链；
- 神经发育 1 篇经核对署名单位为另一医科大学，与本人 2024 年任职记录一致（待确认）。

**说明建议**
建议本人就肿瘤基因组学 2 篇提供署名依据；若为误并，建议向 OpenAlex 提交作者档案更正。
```

注意这个示例的写法：**主动把该篇论文往"正常"方向解释了一遍，然后指出解释不成立的部分**。这是审计报告该有的姿态。

### §4 信号汇总表

把所有脚本信号 + 人工发现合并成一张表，便于快速定位。

| 编号 | 维度 | 信号 | 严重度 | 证据强度 | 对应章节 | 状态 |
|---|---|---|---|---|---|---|
| S0-1 | D0 | 1 篇论文疑为作者误并 | 高 | 二级 | §2 剔除清单 | 已剔除 |
| S2-1 | D2 | 主学科域外论文 33% | 关注 | 四级 | §3.2 | 已解释 |
| S3-1 | D3 | 1 篇命中预警名单 | 高 | 一级 | §3.3 | 待说明 |

"状态"列必须是：已排除 / 已解释 / 待说明 / 建议核查。**不允许出现"确认问题"**。

### §5 剔除清单（身份误并）

仅当 D0 命中时出现。列：论文、DOI、判定为误并的依据、剔除后对指标的影响（如"年均产出由 2.4 降至 2.1"）。

保留这一节很重要——它证明审计者做了自我纠错。

### §6 综合结论

按 `audit_rubric.md` 的综合定级表给出结论。然后：

- 如果结论是"未发现异常"：明确写"本次审计未发现问题，不代表该学者不存在其他未被公开数据反映的问题"。这句话保护报告本身。
- 如果结论是"需说明的疑点"：列出需要本人说明的具体问题（编号化），并给出说明的合理期限建议。
- 如果结论是"高度可疑"：写明建议移送的机关与依据的规则名称，**不写处分建议**。
- 如果结论是"证据不足"：写明缺什么材料、通过什么途径可以取得。

### §7 附录

| 附录 | 内容 |
|---|---|
| A | 论文全清单（编号、年份、标题、期刊、DOI、位次、基金、数据源） |
| B | 检索记录表（数据源、检索式、日期、命中、纳入） |
| C | 基金核查记录（批准号、项目名称、负责人、单位、起止、核查结论） |
| D | 期刊核查记录（刊名、ISSN、收录状态、预警名单、核查日期） |
| E | 原始数据文件清单（JSON/MD 文件路径） |
| F | 已排除的疑点及排除理由 |

## 写作纪律

1. **不用形容词**。"严重""极其""明显"这类词在审计报告里没有信息量。用数字和事实替代。
2. **不用反问句、感叹号**。
3. **一段话只讲一件事**，段落不超过 5 行。
4. **表格优于叙述**。并列信息一律表格化。
5. **每个"首次出现"的缩写给全称**（NSFC、SCIE、APC、OA）。
6. **时间一律写完整年月日**，不写"去年""近期"。
7. **引用论文时给 DOI**，不给标题就完事。
8. **不确定的地方写"未核实"**，不写"应该是"。
